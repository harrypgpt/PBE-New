## 1. Objective (plain language)

People in an organisation can:
- create **projects** (one generic product under study) with controlled terms for dosage form, route and release type;
- see at once whether the product is **within PBE's supported scope**, and if not, **why** (ADR-011);
- add **scenarios** F001, F002 … per project (alternative formulations or study situations, filled with evidence from Stage 9 on);
- see a **dashboard** with their identity, organisation, projects and their status, pending tasks, a recent-runs placeholder and quick actions.

Excluded (roadmap): evidence entry, runs.

## 3. Data ownership and tenant boundaries

- **Tables** (schema `app`, one migration, `expand`):
  - `project` (tenant_id, id, name, molecule, strength_value, strength_unit, dosage_form, route, release_type, product flags, scope_status, scope_reason, scope_vocabulary_version, status, created_by, timestamps);
  - `scenario` (tenant_id, id, project_id, code, description, created_by, timestamps);
  - if D8-6 B: `project_department`.
- Each table follows the Stage 3 template:
  - `tenant_id`, primary key (tenant_id, id), composite foreign keys including `tenant_id`;
  - RLS **enabled and forced**; one tenant policy for `pbe_app`;
  - no PUBLIC rights; `pbe_app` SELECT/INSERT/UPDATE only (no DELETE, never TRUNCATE);
  - `SELECT` for `pbe_backup` (coverage rule from migration 0005).
- **Scope status is computed by the API** from the vocabulary and stored with the vocabulary version, so a later vocabulary change is visible. The database checks consistency: `unsupported` always has a reason.
- **The organisation owns its projects.** The Super Admin sees none without break-glass (read-only).

## 4. Audit

Every project creation, change and archive, and every scenario addition or change, writes one `audit.audit_event` row **in the same transaction** (as in Stage 7A). Rows hold the target, action and request id, with digests and never raw content. Reading the trail is Stage 28.

- **Project page:** details, scope badge with reason, status, scenario list (code, description), "Add scenario", archive.
- **Accessibility and patterns** as Stage 7B: axe 0 violations, keyboard only, plain-language errors.
