## 6. Problems found and fixed (root cause, then fix)

1. **Zod tripped the content security policy.** When it starts, Zod (the shared validation library) tests whether `eval` is allowed. The browser blocked and reported it as a violation. Fix: the website sets Zod's documented `jitless` option (`src/zod-config.ts`), loaded before the contracts. The CSP was not loosened, and the API is unaffected.
2. **`'strict-dynamic'` let injected scripts run.** Next.js's recommended policy includes `'strict-dynamic'`, which lets any trusted script add more scripts. A test showed an inline script added by page code still executed. Fix: `'strict-dynamic'` removed. Script files must come from this site and inline scripts need the per-request nonce. The site still works (S5-10 checks hydration). A second test plants attacker markup in the real page HTML: an inline script, an `onerror` handler and an external script are all blocked.
3. **`next dev` created an `AGENTS.md` file in `apps/web` without being asked.** It is generic Next.js text and not part of the approved scope. Deleted, and switched off with `agentRules: false`. Re-run confirmed no file is created.
4. **Forwarding address is fixed at build time.** Next.js bakes `/api/v1` forwarding into the build, so the planned "second website pointed at a dead API" test could not work. Instead, the browser tests start and stop a real API themselves, so "API not reachable" is a real condition (S5-6). `PBE_WEB_API_ORIGIN` therefore applies when building (default `http://127.0.0.1:3001`).
5. **Folder name clash with the boundary rule.** Fixed by renaming the folder, not by changing the rule.
6. **Test mistakes fixed:**
   - a colour pattern matching `white-space`;
   - two locators also matching Next.js's hidden route-announcer alert;
   - one test clicking a form after leaving its page;
   - one mislabelled test removed and replaced by a unit test of the showcase gate.
