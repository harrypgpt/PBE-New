The project now has a working, empty foundation. There are four workspace packages (web, api, contracts, science-core), each holding only a placeholder and a trivial test. One command, `npm run verify`, runs 10 checks and printed **10/10 PASS** after a clean install from the lockfile. Each guard was shown to **fail** on a planted violation and to **pass** on clean code. No application features, database or Python were introduced, and nothing was committed or pushed.

## 10. Security and scientific implications

**Security:**
- **Audit:** 20 **moderate** npm audit findings, all from one advisory, GHSA-hp3w-g68c-fv3c: `sprintf-js` denial of service. The chain is `sprintf-js` → `argparse@1` → `js-yaml@3` → Jest's coverage tooling. npm reports no version of `sprintf-js` without it ("*"). The only offered "fix" downgrades ts-jest, which is a breaking change.
  - Exposure: dev-time test tooling only, never shipped, and it processes only our own files.
  - High/critical: 0. The gate (`--audit-level=high`) passes.
  - Recommendation: accept for now and re-check at every stage. **This needs the owner's explicit acceptance.**
- **Deprecation:** `glob@10.5.0` (transitive, from Jest) is flagged deprecated by its author. No advisory is reported for it. It will be resolved by future Jest updates.
- **Install scripts:** denied by default (§4). This reduces supply-chain risk and guarantees no Python invocation.

**Scientific:** none. `science-core` is a placeholder. Its purity rules (no I/O, clock, randomness, database or AI) are now enforced ahead of any scientific code.

## 11. Problems found, fixes made, reruns
1. **`.gitignore` deletion (investigated first).** The file was created in `7976b25` and never modified. It survived the "remove old code" commit `d1ec8dd` and was deleted only in the working tree, consistent with the owner's from-scratch cleanup. Its content is generic and contains no secrets. It was restored with `git restore .gitignore` (nothing to overwrite) and is byte-identical to HEAD.
2. **TypeScript peer warning during install.** npm warned while resolving TypeScript. Investigation: typescript-eslint requires TypeScript `<6.1.0`, so npm installed 6.0.3 rather than 7.0.2. `npm ls --all` exits 0 (no invalid peers). No change was needed.
3. **Install scripts** flagged by npm. They were denied explicitly (§4), and the tests were re-run and pass.
4. **ESLint inside Jest.** ESLint loads the ESM config file with a dynamic import that Jest's sandbox does not support. Lint self-tests therefore run ESLint in a child process (`lint-probe.cjs`).
5. **Formatting.** Prettier re-wrapped long lines in the new tooling files once (`npm run format`). There was no logic change.
6. **Mutation-check set-up error** (§7): corrected and rerun.
